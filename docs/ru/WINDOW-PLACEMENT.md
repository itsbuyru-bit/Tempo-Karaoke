# Окно, DPI и запуск

Документ описывает размещение главного окна, сохранение пользовательского
положения и ускорение старта. Реализация: `Services/WindowPlacementService.cs`,
`Services/WindowPlacementMath.cs` (Core), `Services/StartupTrace.cs`,
`MainWindow.xaml.cs`, `MainPage.xaml.cs`.

## Стартовый размер и центрирование

Размер считается от **рабочей области** текущего монитора (без taskbar), а не от
физического размера экрана в дюймах:

```
minWidth  = 1024 DIP     minHeight = 700 DIP
maxWidth  = 1920 DIP     maxHeight = 1200 DIP
width  = clamp(workArea.DIP.Width  * 0.75, minWidth,  maxWidth)
height = clamp(workArea.DIP.Height * 0.75, minHeight, maxHeight)
x = workArea.X + (workArea.Width  - width)  / 2
y = workArea.Y + (workArea.Height - height) / 2
```

Пределы заданы в DIP и переводятся в физические пиксели по масштабу монитора
(`GetDpiForMonitor`), поэтому на 4K при 150% окно не становится гигантским.
`AppWindow.MoveAndResize` принимает физические пиксели — конвертация выполняется
в `WindowPlacementService`.

## Сохранение положения

`settings.json`:

```json
{
  "Window": {
    "UserPositioned": true,
    "Maximized": false,
    "X": 100,
    "Y": 80,
    "Width": 1200,
    "Height": 800,
    "DisplayId": "\\\\.\\DISPLAY1",
    "DpiScale": 1.5,
    "SavedAt": "2026-11-06T23:00:00Z"
  }
}
```

- `X/Y/Width/Height` — **DIP относительно рабочей области** дисплея, поэтому
  перенос настроек на монитор с другим разрешением/DPI не даёт окно за экраном.
- `DisplayId` — имя устройства Win32 (`\\.\DISPLAY1`), `DpiScale` — масштаб на
  момент сохранения (диагностика и миграция).

Запись выполняется **только после реального изменения** окна пользователем:
подписка на `AppWindow.Changed` (`DidPositionChange`/`DidSizeChange`/
`DidPresenterChange`), debounce 800 мс. Программные изменения (стартовое
центрирование, сброс, прижатие к экрану) выполняются под флагом
`_applyingPlacement` и не сохраняются. Свёрнутое окно пропускается; при
максимизации сохраняется флаг `Maximized` и последний «нормальный» прямоугольник.

## Восстановление и валидация

1. Нет `UserPositioned` → окно по центру с размером по умолчанию.
2. Есть `UserPositioned`, но `DisplayId` больше не существует (монитор
   отключён) → окно по центру на текущем/первичном мониторе.
3. Сохранённый прямоугольник проверяется: видимая часть должна быть не меньше
   100 DIP по каждой стороне и 20% площади; размер ограничивается
   минимумом/максимумом и рабочей областью, позиция прижимается к экрану.
4. Невалидный/офскрин/слишком большой прямоугольник сбрасывается на
   центрированный размер по умолчанию.
5. `Maximized` восстанавливается после применения нормального прямоугольника.

Миграция: старые `settings.json` без блока `Window` открываются по центру; блоки
с координатами от другого монитора автоматически признаются невалидными
(проверка видимости и clamp).

## Сброс положения

- Параметры → «Положение окна» → **«Сбросить положение окна»** (применяется
  сразу, без перезапуска).
- Командная строка: `TempoKaraoke.exe --reset-window` (сбрасывает сохранённое
  положение при следующем запуске).

## Мониторы и DPI

- Перечисление мониторов — Win32 `EnumDisplayMonitors`/`GetMonitorInfo`:
  `DisplayArea.FindAll()` в unpackaged-сборке падает с «class not registered»,
  поэтому он остаётся только запасным путём для рабочей области окна.
- DPI каждого монитора — `GetDpiForMonitor`; масштаб текущего окна —
  `GetDpiForWindow`. Манифест объявляет `PerMonitorV2`.
- `DisplayAreaWatcher` (Added/Removed/Updated) и `XamlRoot.Changed` вызывают
  проверку: окно прижимается к рабочей области текущего монитора, при смене
  масштаба обновляется сохранённый `DpiScale`.

## Ускорение старта

- `StartupTrace` пишет вехи в лог всегда (даже при выключенном логировании):
  `ProcessStart`, `App ctor done`, `OnLaunched`, `MainWindow ctor`,
  `Window placed`, `Navigate -> MainPage`, `MainPage ctor (done)`,
  `Window activated`, `MainPage loaded`, `First render`, `Deferred init`,
  `UI interactive` и сводную таблицу `Startup timeline`.
- Тяжёлые операции страницы (`InitializeAfterFirstRender`) выполняются после
  первого кадра: плейлисты, очередь, недавние, обновление списка устройств
  пульта. Каждый блок в `try/catch` с записью в лог — сбой не ломает запуск.
- Медиатека сканируется асинхронно (как и раньше), проверка обновлений
  запускается после `Loaded`.
- Пример на машине разработчика: первый кадр ≈ 750 мс, `MainPage ctor` ≈ 120 мс,
  отложенная инициализация ≈ 5 мс.

## Ограничение по экрану загрузки

`MainPage` создаётся **до** `Window.Activate()`: если создать страницу после
активации, MRT не разрешает ресурсы `x:Uid` и загрузка падает
(`Unable to resolve property ... Uid ...`). Поэтому отдельный splash/overlay не
показывается — окно появляется уже с интерфейсом, а «чёрное окно» устраняется
тем, что тяжёлая работа вынесена после первого кадра. Если понадобится явный
индикатор, его нужно делать отдельным лёгким окном.

## Проверка

Ручные сценарии: первый запуск на 1080p и на 4K/150%; перенос настроек с 4K на
1080p; перемещение на второй монитор и перезапуск; отключение второго монитора;
смена масштаба 100% → 150%; maximized и восстановление; ручное уменьшение окна до
минимума; повреждённый `settings.json`; `--reset-window`.

Автотесты: `WindowPlacementMathTests` (размер, центрирование, clamp, видимость,
офскрин, минимальный размер) и `XamlResourceUidTests` (запрет `x:Uid`,
отличающихся только регистром — из-за такой пары приложение не открывало
главную страницу).
