# Tempo Karaoke — правила для агента

## Перед кодом

1. Для новой фичи, архитектурного решения или неоднозначной задачи сначала вызови
   `/grill-me`: по одному вопросу через `ask`, пока не закрыты платформа,
   воспроизведение, данные, поиск, плейлисты и критерии приёмки.
2. Стек выбран: **WinUI 3 + LibVLCSharp**, спайк проверен (см. `README.md`).
   Перед каждой новой фичей всё равно вызывай `/grill-me` — требования и объём
   ещё не зафиксированы.
3. Если ответ можно найти в репозитории, файлах или документации — найди сам, не
   спрашивай.

## Проект

- Приложение: караоке-плеер с библиотекой, очередью и умным поиском.
- Медиатека `G:\Karaoke` — **только чтение**. Не копировать, не переименовывать, не
  коммитить медиафайлы и не хардкодить путь как единственный корень.
- Индексировать **только видео** (`.mkv`, `.mp4` и другие видеорасширения). `.mp3`
  не включать в список и поиск.
- В файлах одна аудиодорожка со встроенным текстом песни: не делать переключение
  дорожек «минус/плюс» и не строить под это UI.
- UI и сообщения — по-русски; код, имена файлов и технические термины — как есть.
- `README.md` — продукт и архитектура; `SKILLS.md` — установленные скиллы и
  источники.

## WinUI 3

- Перед изменением XAML прочитай `winui-design`.
- Перед коммитом UI-кода — `winui-code-review`.
- Для проверки API используй `winapp find-api`, для контролов — `winapp find-ui`,
  а не догадки.
- Сборка/упаковка — через `winapp` (0.7.1), см. `winui-dev-workflow`.

## Качество

- Проверяй изменение ближайшим релевантным тестом или сборкой; не заявляй «готово»
  без прогона.
- Не оставляй в репозитории временные файлы, логи и скачанные медиа.
- Не делай `git init`, `git commit` или изменения в родительском репозитории без
  явного разрешения.
